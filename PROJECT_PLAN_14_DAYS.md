# Ориентировочный план реализации на 14 дней
## ИИ FAQ/RAG-ассистент для vassian.ru

Этот план подготовлен в формате, требуемом учебным чек-листом. Он описывает разумную последовательность реализации проекта, а не утверждает, что фактическая разработка заняла ровно 14 календарных дней.

## День 1 — постановка задачи

- определить цель ассистента;
- описать аудиторию;
- выделить основные типы вопросов;
- определить границы ответственности;
- зафиксировать критерии приёмки.

**Результат:** согласованное ТЗ.

## День 2 — сбор базы знаний

- собрать FAQ;
- собрать информацию об услугах;
- собрать подтверждённые факты о специалисте;
- собрать описания кейсов;
- отделить неподтверждённую информацию.

**Результат:** первичная база знаний.

## День 3 — проектирование системного промпта

- определить роль;
- определить стиль;
- сформулировать главное правило источника истины;
- описать поведение при отсутствии информации;
- добавить ограничения;
- добавить защиту внутренних инструкций.

**Результат:** первая версия system prompt.

## День 4 — проектирование RAG

- определить формат документов;
- подготовить нормализацию FAQ и текстовых файлов;
- выбрать векторный индекс;
- определить metadata документов;
- определить количество retrieved-фрагментов.

**Результат:** схема RAG и подготовка документов.

## День 5 — embeddings и FAISS

- подключить embedding-модель;
- построить индекс;
- сохранить metadata;
- проверить retrieval на типовых вопросах.

**Результат:** рабочий поиск по базе знаний.

## День 6 — генерация ответа

- собрать цепочку `system prompt + RAG context + user message`;
- подключить AI-провайдера;
- проверить ответы на FAQ;
- проверить неизвестные вопросы.

**Результат:** первый end-to-end диалог.

## День 7 — память диалога

- добавить `session_id`;
- сохранять историю сообщений в SQLite;
- передавать ограниченную историю в модель;
- проверить независимость разных сессий.

**Результат:** многоходовой диалог.

## День 8 — follow-up retrieval

- протестировать вопросы с местоимениями и ссылками на предыдущий контекст;
- выявить потерю референта при embedding только текущей фразы;
- добавить предыдущий пользовательский вопрос в retrieval query;
- не использовать сгенерированный ответ ассистента как источник retrieval.

**Результат:** корректная обработка уточняющих вопросов.

## День 9 — API

- реализовать `GET /health`;
- реализовать `POST /chat`;
- описать модели входа/выхода;
- настроить CORS;
- исключить утечку внутреннего RAG-контекста.

**Результат:** готовый backend API.

## День 10 — веб-виджет

- создать простой чат-интерфейс;
- подключить API;
- реализовать хранение `session_id` на стороне клиента;
- подготовить вариант встраивания на сайт.

**Результат:** работающий пользовательский интерфейс.

## День 11 — автоматические тесты

Проверить:

- API;
- создание и повторное использование сессии;
- историю сообщений;
- работу без индекса;
- загрузку базы знаний;
- наличие индекса;
- contextual retrieval query.

Использовать fake AI provider, чтобы тесты выполнялись без реальных API-ключей.

**Результат:** воспроизводимая техническая проверка.

## День 12 — prompt-evaluation

Провести ручные сценарии:

- обычный FAQ;
- неизвестный факт;
- цена;
- срок;
- гарантия;
- follow-up;
- prompt injection;
- попытка раскрытия system prompt;
- попытка получить сырой RAG-контекст.

**Результат:** заполненный набор prompt test cases.

## День 13 — production-развёртывание

- разместить backend на VPS;
- подключить systemd;
- настроить reverse proxy;
- включить HTTPS;
- встроить виджет в vassian.ru;
- проверить production API и диалог.

**Результат:** работающий публичный проект.

## День 14 — документация и финальная приёмка

Подготовить:

- ТЗ;
- описание prompt design;
- prompt test cases;
- инструкцию обновления базы знаний;
- документацию запуска;
- описание архитектуры;
- ссылку на работающий проект и репозиторий.

Провести финальную проверку критериев приёмки.

**Результат:** проект готов к сдаче и добавлению в портфолио.

5. FAISS-индекс.
6. Backend API.
7. Веб-виджет.
8. Автоматические тесты.
9. Набор prompt-evaluation сценариев.
10. Документация по обновлению базы знаний.
